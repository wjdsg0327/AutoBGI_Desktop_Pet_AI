# 桌宠领域数据接口核验

核验日期：2026-10-27。以下结论来自本次实际工作区源码与隔离数据验证，不代表旧版 AutoBGI 已发布这些接口。

本文的旧培养摘要和后附执行链审计保留阶段性基线。当前 0.2.5 已新增正式队列存储、纯评估、网页编辑及桌宠独立只读接口，最新合同见 `cultivation-queue.md`；可信库存、启动事务与培养完成事件仍未开放。

## 接口与身份范围

所有接口位于 `/api/desktop-pet/v1`，使用桌宠协议统一 `apiKey` 请求头鉴权和 `code/message/requestId/serverTime/data` 响应。错误不回显服务器路径、数据库原始异常或凭据。

| 接口 | 输入 | 数据来源与边界 |
| --- | --- | --- |
| `GET /query-roles` | 不接受任何查询参数 | 已有米游社绑定缓存的安全复制快照，列出可用 UID+区服 |
| `GET /scan-accounts` | 无查询参数 | `BagScan.Accounts`，仅枚举真实扫描记录目录 |
| `GET /backpack` | 必须显式提供一个 `scanAccountId` | `BagScan.LatestAccountSnapshot`，仅所选目录的最新扫描块 |
| `GET /earnings` | 可选 `date=YYYY-MM-DD`、`queryRoleId` | 指定缓存角色或兼容默认角色 UID 的摩拉总账 |
| `GET /cultivation-plans` | 可选各一个 `scanAccountId`、`queryRoleId` | 实例 `CharacterPlan` 配置、指定角色面板及精确匹配的已有官方需求缓存 |
| `GET /cultivation-queue` | 必填单个 `presetId` | 正式持久队列的绑定身份、明确目标及精确缓存需求；独立能力，不接受查询角色替代计划身份 |

扫描账户不是游戏账户或执行账户。空 `scanAccountId=` 明确选择旧版根目录；省略参数不能在背包接口悄悄选择默认用户。非法、重复、未知查询参数（包括通用 `accountId`）返回 400。扫描账户消失返回 404；源数据暂不可用返回 503 `DATA_UNAVAILABLE`，不会用零值冒充数据。

能力声明包含扁平 `features.queryRoles`、`scanAccounts`、`backpack`、`earnings`、`cultivationPlans`。通用 `accounts` 仍为 false，执行范围仍为实例；这些只读接口不提供游戏账号切换。

## 绑定缓存与查询选择

- `queryRoleId=mys-role:<region>:<uid>` 只标识查询上下文；列表由已有绑定缓存过滤、去重，不触发 `InitA`、Cookie 读取或网络刷新。
- 列表来源为 `mihoyo-binding-cache`；时间只来自缓存文件修改时间或原有刷新流程读取时刻，未知为 null。缓存条目不能证明当前登录身份或当前 Cookie 授权。
- 缓存读取和既有写入使用同一互斥锁，返回列表副本。默认项只映射实际配置默认角色；原默认角色无效时不猜选另一个。
- 列表有效输出最多 200 个角色，原始输入最多 1000 项，超限失败。非法标识 400，合法但消失标识 404，缓存不可用 503。
- 桌宠保存角色列表供选择，但角色选择只存在于手动业务摘要。切换立即清除原角色数据，迟到响应按请求版本、连接资料、代次和实例拒绝；同一上下文普通状态广播保留摘要。
- 列表失败或显式角色消失时，收益和培养保持空并说明错误，独立扫描背包可继续。角色选择不修改服务端默认角色、连接资料、实例快照或执行账户。

## 背包

- 复用现有记录目录边界、普通文件校验、文件大小限制和材料解析器。
- `BagScan.LatestAccountSnapshot` 为原有 `LatestAccount` 提供共享实现，保留最新空扫描的真实扫描时间。最新扫描为空或包含 `×?` 时不回退旧库存。
- `scannedAt` 来自扫描块时间，不使用文件修改时间或接口请求时间；无可确认时间则返回不可用。`timezone` 明确服务器当前本地时区与偏移。
- `version` 为所选目录标识与最新扫描块内容的 SHA-256 摘要；不包含绝对磁盘路径。
- 扫描文件没有可靠官方材料 ID。列表 `id` 使用 `scan-name:` 命名空间，只用于稳定展示；不与培养官方材料 ID 等同。
- `completeness=recognized-items-only`：仅返回明确识别的整数数量。未识别、缺席和超出整数范围的数量都不能被当作零。
- 接口不会启动扫描，不会合并其他扫描目录或旅行札记库存。

## 收益

实际权威来源为 `models.MoraleRecord` 和 `models.BuildMoraleIncomeBook`，沿用 `bgiStatus/DailyReport.go` 的日归档优先读取规则。

- 省略 `queryRoleId` 时使用 `config.CurrentGameRole()` 的真实 UID；显式选择时严格验证绑定缓存成员并返回匹配的 `queryRoleId/currentRole`。不从扫描目录名称推断 UID。
- 摩拉表没有区服字段；同 UID 在当前缓存中绑定多个区服时拒绝显式角色收益，避免把无法区分的账本归给某一区服。
- 先查所选日的 `record_type=day` 归档，有归档时不重复累计明细。零归档也保持零，不因为数值为零改读历史明细。
- 无日归档时再查该日明细，UID 与日期均严格过滤。没有记录返回不可用。
- 总额与精英、小怪、宝箱分类复用现有总账聚合，不复制分类算法；不调用可能压缩或写回记录的旧 HTTP 处理器。
- 单位为摩拉。未核实的狗粮金额、游戏业务日刷新时间不编造；`businessDate`、`resetTime` 保持 null，`date` 是既有数据库归档使用的日历日期。标准字段 `timeZone` 明确实际时区，兼容字段 `timezone` 保持相同值。
- 桌宠读取“今日收益”时省略 `date`，由服务器确定当天，避免跨时区连接误用客户端日期；显式指定日期时仍严格校验返回日期。客户端的五个日期边界用例已在 race 下通过。
- `updatedAt` 只来自可解析的记录时间，不把总账对象构建时间当作数据更新时间。

## 培养

旧 `/cultivation-plans` 的业务来源是 `CharacterPlanService`、`models.CharacterPlan` 与 `characterDevelopment`，不会因新增 `TalentPlanService` 而自动变成执行队列。正式保存顺序由独立 `/cultivation-queue` 返回，仍没有可推进的可信执行链。

- 计划按持久 ID 升序返回，状态为 `configured`。这表示配置顺序，不表示当前排队、执行中或已完成。
- `queueAvailable=false`、`completionEventsAvailable=false`。不根据材料齐全、缺口为零或计划为空发送培养完成通知。
- 新增 `CharacterPlanService.ReadCachedCharacterRequirements`，严格要求完整 UID/区服并核对缓存正文身份。
- 面板读取复用 `Mihoyo.LoadCharacterInfoFromCache`；材料仅命中现有计算器完整元素、等级、技能组、天赋和目标请求的已验证缓存。
- 缺少计算缓存时保留面板等级和天赋，`requirementsAvailable=false`，不补拉网络，不修复或写入缓存。
- 材料需求、元素匹配、目标构建与官方结果校验复用现有计算器逻辑。相同官方材料 ID 的角色和天赋需求合并。
- 计算器默认目标（通常等级 90、三项天赋 10）以 `targetSource=calculator-defaults` 明确标注；正式计划的首领材料、天赋书开关单独返回，不能把默认计算目标伪装为计划保存的 A/E/Q 目标。
- 兼容默认角色路径仅当显式扫描确实包含材料名时填充 `owned` 和 `missing`；未选择扫描账户或材料未识别时，两者均为 null。显式查询角色路径没有扫描身份绑定，即使选择扫描目录，两者仍必须为 null。
- 计划名称拆分复用正式服务的分隔与去重规则，但不调用写入校验中的 `FindCharacterData`，因为该校验可能联网获取缺失角色资料。

## 验证与限制

使用临时 SQLite 和临时背包目录验证接口；模拟数据与真实配置、库存、角色面板和生产运行状态无关。

已覆盖的行为：

- 显式扫描账户隔离、重复/未知/穿越参数拒绝、已消失扫描账户。
- 最新空扫描保留扫描时间与内容版本，未知数量不回退历史库存。
- 零日归档优先于非零明细，其他 UID 收益不被合并，非法日期和无记录日期正确失败。
- 计划元数据不会冒充执行队列，缺失面板/需求保持未知。
- 官方计算缓存精确命中与合并，等级改变后旧需求失效。
- 培养需求查询不发起 HTTP 请求、不创建/更新/删除数据库记录。
- 扫描明确识别的材料得到正确缺口，未识别材料的已有数量和缺口保持 null。

验证方式为先 `go test -c` 编译测试可执行文件，再在独立临时工作目录执行，避免现有 `config.init` 改写包目录运行配置。临时测试源码与测试可执行文件在验证结束后删除；主模块版本保持 `go 1.27.0`，未修改 `go.mod`。

另外使用真实 `desktopPet.New/RegisterRoutes`、随机回环端口与只增加内存计数的模拟提供器，联调桌宠真实 `PetV1Adapter`。开启 Go race 检查后，能力协商、快照、配置列表、相同命令 UUID 重复提交只派发一次、SSE `command.updated → succeeded` 与 GET 回执核对通过。该验证没有使用生产菜单提供器，也没有启动 BetterGI 或原神；临时服务、源码、可执行文件和命令记录在联调后关闭并清理。

首次执行未隔离的包测试时，现有 `config.init → ReloadConfig` 重写了旧有、被 `.gitignore:6` 忽略的 `CharacterPlanService/main.json`，包括测试可执行文件 `BasePath`、日志选择和缺省字段规范化。该文件创建于 2026-10-23，原文未被 Git 跟踪且包目录无备份，因此没有猜测覆盖或删除旧配置。根目录 `main.json` 未被本子任务更改。新生成的 `desktopPet/main.json` 属于本轮测试副产物，清理后不作为交付内容。

本次不宣称真实 AutoBGI 服务、米游社在线数据、游戏执行、扫描触发或培养执行经过端到端验证。

0.2.2 使用真实 Gin `RegisterRoutes` 与桌宠真实 `Service/PetV1Adapter` 进行了四组隔离联调，服务端和客户端均开启 race：双角色交替收益与培养、明确默认解析、失效成员拒绝、旧服务能力缺席、鉴权、默认配置和执行计数不变均通过。SQLite、配置、模拟角色与命令日志均为临时隔离数据；提供器的执行计数始终为零。

## FIFO 培养执行链的补充源审计

本节保留本轮实现前的源码审计。之后新增的正式队列持久层、明确目标计算、纯评估器和网页 API 见 `cultivation-queue.md`；本节中“尚无实现”的描述对应审计时快照，不代表这些准备模块仍然缺失。可信库存、启动提交和完成事件仍未开放。

以下为 2026-10-27 对当前源码和本地 Git 对象的只读核对。规格 10.5、M4 中的正式 FIFO 推进、排除摩拉和智识之冕的完成判定、真实完成事件及全部完成后继续启动，当前仍未实现。本节记录补齐条件，不表示这些拟议合同已经存在，也不以历史记录或隔离测试代替生产实现。

该 tree 不能原样恢复，源码中至少有以下适配缺口：

- 历史 `Prepare.go/domainSettingKeys` 仍根据 `WeeklyDomainEnabled` 选择每周字段；新培养流程必须按每日秘境合同实现。
- 历史 `Evaluate` 只计算天赋书；它同时忽略了周本、怪物等其他需求，不能据此声称已实现“仅摩拉和智识之冕不影响完成”的完整规则。
- 历史普通进度读取把 `time.Now()` 赋给 `InventoryAt`，实际库存可能来自缓存；请求时刻不能冒充库存源时间。
- 历史 `RefreshBagInfo` 虽绕过旧缓存且失败不回退，返回值仍没有 UID/区服的来源证明，不能直接授权角色完成判定。
- 历史 `savePlan` 计算了通知状态重置值，但冲突更新列未包含 `notice_json`；重新加入角色后的重置不能保证落盘。
- 历史 `ApplyEvaluation` 同时按完成条目 ID 或角色名移除当前记录；旧评估可能误删用户刚重新加入的同名新条目，需要版本与稳定条目 ID 的条件提交。
- 历史启动准备先移除队列，再写自动配置和发送通知，没有把最终启动拒绝、配置摘要变化及数据库/文件/进程之间的失败边界纳入提交协议。

以上是对指定历史 tree 的静态结论，不是当前检出文件的新增运行缺陷，也没有宣称这些历史路径经过本轮运行测试。

### 库存来源的身份与时间缺口

当前 `config/BagInfoCache.go/bagInfoCacheRecord` 使用统一键“背包统计”，保存 `cachedAt`、分类和材料数量，没有 UID、区服或源版本。`config/YuanShen.go/TreeResponse2` 只解析 `material_info`；现有 `sync_game_material_info` 请求和解析结果没有可用于核对库存所属角色的字段。请求使用某份 Cookie、`CurrentGameRole()` 返回某个角色，都不能单独证明该材料响应属于这个 UID 和区服。

`JsScript/BagScan/AccountSnapshot` 只提供扫描块时间、内容版本和识别条目；`accounts.go` 明确把扫描目录名作为档案标识，目录名称并非经过核验的游戏 UID。现有显式查询角色接口因此继续把扫描库存与角色需求分开，`owned/missing` 保持 null。

正式推进必须先增加可信库存提供器，返回明确来源的 `UID + region`、身份核验依据、实际源时间、读取时刻、内容版本、新鲜度和覆盖范围。不能把当前配置角色补写到无身份库存上；不能把缓存读取时刻当作源时间；也不能把 `recognized-items-only` 中缺席的物品当作零。身份、覆盖范围或新鲜度无法核实时，只返回警告、保留队列和手动配置，并继续原一条龙启动。

| `InventorySnapshot` | 角色、身份核验依据、来源、真实 `sourceTime`、独立 `fetchedAt`、版本、新鲜度、覆盖范围和材料数量；来源无法证明身份时不得用于推进 |
| `RequirementSnapshot` | 角色、角色 ID、当前/目标状态、完整计算请求指纹、来源时间及材料；复用 `CharacterPlanService` 的官方请求构建、校验和精确缓存，不在客户端另建需求算法 |
| `Evaluate(input)` | 纯评估，不联网、不写配置或数据库；只产生可完成的连续 FIFO 前缀，虚拟扣减前序占用库存，输出当前角色、剩余目标、每日秘境候选、警告和 `applyAllowed` |
| `ReadProgress` / `RefreshSources` | 读取已有进度与显式采集分开；前者不因打开桌宠面板触发采集，后者仍不自动推进队列 |
| `PrepareStart` | 只读冻结队列版本、角色、来源版本/时间、输入配置摘要、完成前缀和允许的每日配置差异 |
| `BeginCommit` | 所有确定未派发的最终检查通过后，以队列版本和配置摘要进行条件提交；仅暂存可逆配置差异和持久操作意图，尚不移除队列或发布完成事件 |
| `FinalizeStarted` / `AbortStart` | 派发成功后事务移除仍匹配的完成前缀并写去重事件；确定未派发时只条件恢复仍等于自动写入值的字段，不推进队列、不发布完成事件 |

材料必须由服务端逐项标明是否参与完成判定。摩拉和智识之冕不参与；其他需求不能因为不便计算而一并忽略。材料 ID、名称及可合成关系复用权威来源和已有服务端映射，不能把显示名称近似匹配当作身份依据。正常空队列应是“暂无计划”；只有原队列非空且经过可靠评估提交后才能产生“全部完成”，并提示添加新计划。全部完成仅停止自动填充培养秘境，原一条龙继续运行。

自动字段需要保存 `original/written/operationId`，恢复时逐字段比较。用户在自动写入之后更改过的字段必须保留；队列、配置或身份版本改变时，旧准备结果不能提交。执行准备必须使用正式计划绑定的执行角色，桌宠的只读查询角色选择不得改变该角色或一条龙目标。

数据库事务、配置文件原子替换与 `exec.Start` 无法组成一个事务。确定未派发的配置/进程检查必须发生在队列提交之前；冻结输入摘要须先核对，随后只允许应用已冻结的每日差异，并在派发前复核产物。不得为适配培养流程删除当前桌宠入口的摘要、空闲检查、单次派发或不自动重试约束。若已经派发而最终数据库提交失败，应保留待核对操作且不自动重发、不宣称完成，后续通过新的可信评估恢复。

预计变更应覆盖服务端队列模型及迁移、纯评估与来源适配、显式目标计算缓存、身份可信库存提供器、统一启动钩子、每日配置条件恢复、配置重命名/删除生命周期，以及现有网页队列编辑入口。桌宠侧只增加真实进度和事件 DTO/适配、能力协商与展示。当前客户端校验明确拒绝尚未实现的队列语义，因此新增真实队列时还需要独立能力或版本合同，不能仅把现有 `queueAvailable` 改成 true 就声称兼容。

验证必须分别覆盖纯评估、身份与源时间、目标缓存精确匹配、只完成连续前缀、虚拟库存分配、忽略摩拉/智识之冕、全部完成仍启动、最终拒绝不推进、派发/落盘故障、通知去重及后续人工设置保护。当前这些 FIFO 合同尚无实现或对应测试结果；本节只完成源审计与提交边界说明。
