# 本地通知历史与未读摘要

本轮补齐开发文档第 11.3、12 节的通知持久化边界。事件游标、已处理身份、命令回执和安全通知正文写入同一个有界 JSON 日志，通过同目录原子替换一起提交。只有提交成功的新提醒才能进入当前进程的气泡队列。

## 通知历史

`Journal.notificationScopes` 保存完整来源：连接资料 ID、规范化地址、协议模式、实例 ID 和账号字段。当前协议仅支持实例级通知，账号字段必须为空；未完成协议核验时的本地连接错误单独标为 `unverified`，不能冒充 Legacy 或已核验实例。

`NotificationHistory` 与实时 `Notifications` 分开。重启仅恢复历史，不把历史正文重新加入气泡队列，也不从旧命令或旧 attempted 标记虚构正文。当前活动连接的保存地址决定可见历史；不同实例按原来源分别列出。删除连接或修改地址后，旧来源不会重新绑定到新地址。

每条正文分别保存：

| 字段 | 含义 |
| --- | --- |
| `createdAt` | 原始事实发生时间；本地错误使用本地创建时间 |
| `attemptedAt` | 提交前已保留一次交给展示管道的尝试；外部 UI 不保证实际出现 |
| `readAt` | 用户明确执行已读操作的时间 |
| `quietPending` | 尚有资格参与勿扰未读摘要，与已读、展示尝试独立 |

面板新增通知记录、只看未读、单条已读和同来源保留记录批量已读。打开面板、气泡超时、关闭提醒和查看历史都不会自动修改已读。已读请求冻结完整来源和实际编号；地址变化、未知编号、重复编号或混合来源整批拒绝，不能部分修改。

## 勿扰与禁播

勿扰中的新提醒将正文和未读待汇总数一起提交，不进入实时气泡队列。明确标为已读会在同次提交中取消该正文的待汇总资格。勿扰解除后，只对当前精确来源生成一条未读摘要，同时清除该来源待汇总计数并保留摘要展示尝试；提交后才进入气泡队列。

进程在摘要提交前退出，待汇总计数仍保留；提交后退出，重启仅保留未读历史，不再补弹该摘要。配置与通知日志属于不同文件，不承诺两个文件之间的事务；配置已关闭勿扰而日志提交失败时，不发送气泡，重启后重新核对当前来源及日志。

隐藏桌宠、系统休眠和关闭气泡继续采用不补播策略。禁播时消费当前精确来源的待汇总资格，保留正文未读；其他历史来源不会因当前窗口隐藏而被清空。宿主临时禁播入口仅对 Go 宿主开放，不提供 WebView 绑定。展示层启用 `QuietManaged`，不再自行计数或生成第二条勿扰摘要。

## 容量、失败与兼容

- 最多 40 个来源，每来源最多 200 条正文，总计最多 1,000 条；每条正文最多 1,000 个字符并受字节限制，整个日志仍受 16 MiB 上限约束。
- 优先裁剪最旧已读正文，再裁剪最旧未读正文；裁剪未读会在所属来源标注历史不完整。已裁剪未读的勿扰计数保留，不能将容量清理伪装成用户已读。
- 只有没有未读、没有待汇总计数的来源可被整体淘汰；无法安全容纳新来源时拒绝本次事务。
- 同一来源事实键幂等，不同正文的冲突事实拒绝。有限历史不承诺永久墓碑；命令和材料另沿用各自持久事实及事件去重边界。
- 已有 schema 1 日志缺少新字段时恢复为空通知历史；新通知字段损坏、重复 JSON 字段、错误身份或非法处理时间导致安全拒绝，不覆盖旧文件。
- 任一通知事务无法安全提交时，本次运行停止后续日志写入与新提醒投递，保留已提交正文、游标和已读状态。修复目录后需重新启动桌宠，不在当前会话偷偷重试。
- 日志不保存密钥、HTTP 原始响应、服务端任意错误或原始日志。界面使用纯文本插值。

## 验证边界

实际 Vue/Pinia 源码通过自定义渲染器验证，覆盖打开与筛选不自动已读、来源分页、请求冻结、单条与批量已读、合成身份隔离、迟到回包、纯文本正文、裁剪后的独立计数以及生成绑定允许的空列表。合成账号夹具仅用于界面隔离检查，当前后端仍拒绝账号级通知。

Go 存储、业务事务及独立审查结果，以及最终源码和发布摘要，记录于 `notification-inbox-validation-2026-10-28.json` 和 `acceptance.md`。没有运行真实 AutoBGI、游戏控制、生产账号数据或系统休眠，也没有重新验证 Windows 原生气泡、焦点、快捷键、DPI 或资源占用。250 MB 目标仍未通过。

一次根代理的临时测试组合命令被自动审批拒绝，命令没有执行，也没有生成该目标；没有重试删除该目标。被拦截的精确目标为项目内重复子目录 `AutoBGI_Desktop_Pet_AI/internal/notification/durable_quiet_validation_test.go`。此事项不计为测试通过。

服务代理完成三轮 race 后，单次删除 `internal/service/notification_inbox_20261028_validation_tmp_test.go` 的命令也被自动审批拒绝（`blocked by policy`）。该测试源保留，受 `notification_inbox_validation` build tag 隔离，不参与普通构建，不进入便携包。没有通过其他工具、改名或删除父目录再次尝试清理。实际存储测试源与独立审查 overlay 测试源已成功清理。
