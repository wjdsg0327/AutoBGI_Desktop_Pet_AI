旧的带重试入口现先检查本执行目录全部未决启动及目标配置生命周期，通过之后才执行关闭程序和原启动策略。守卫保留原重试行为，且不执行培养提交；不能据此宣称网页、定时任务、日志触发等入口已经统一实现自动推进。慢启动和重试期间持续持有队列与目录锁，其他队列读取可能等待。

## 服务端合同

`NewStartupService(store, source)` 仅接受宿主注册的来源函数，不开放 HTTP 评估提交。回调取得权威计划的独立副本，返回数据在内部冻结。修改公开操作视图、返回切片或公开评估结果，不能改变私有提交凭据。

| 方法 | 作用 |
| --- | --- |
| `PrepareStart` | 只读计划和来源，用服务自己的当前时钟评估；不占名、不写日志或文件、不移除条目 |
| `StageStart` | 核对完整计划、稳定身份和版本，登记 `prepared` 并持久占用配置名 |
| `BeginCommit` | 使用实际当前时间重评估冻结来源，持久迁移到 `dispatching`，必须先于执行器调用 |
| `MarkDispatched` | 仅在执行器明确成功后登记 `dispatched`，不等待游戏或日志终态 |
| `FinalizeStarted` | 同一事务推进连续前缀、退役稳定 ID、保存去重事件、递增版本并迁移到 `finalized` |
| `Abort` | 仅供宿主证明未派发且已处理设置后使用，不依据超时或重启推断 |
| `PendingStarts` / `StartOperation` | 只读未决或指定记录，不重建可派发凭据 |
| `PendingStartEvents` / `AcknowledgeStartEvent` | 有界读取及幂等确认 outbox，确认后保留去重身份 |

未决阶段都保留名称占用，队列编辑、改名、删除和文件生命周期共同遵守。未知阶段、损坏正文和超量日志不能伪装成没有待处理操作；读取也不能伪装为空队列。

日志保存来源快照、计划摘要、原/目标文件摘要和两个允许字段的原值/自动值，不保存 Cookie、APIKey 或整份一条龙配置。冻结正文上限 512 KiB，每个执行目录最多 32 个未决启动。

## 一次派发与失败边界

`RunPreparedStart` 使用宿主提供的有界文件读取、完整摘要 CAS 和一次派发函数。宿主必须持有统一的队列、目录和启动锁。CAS 必须有真实的安全实现，普通路径写入不能冒充安全替换。

协调器先构造并核对完整目标正文，再登记意图、应用差异、重读实际产物并调用 `BeginCommit`。此时队列仍未移除条目。执行器确认成功后才登记回执并提交队列。

| 失败边界 | 行为 |
| --- | --- |
| 来源明确缺席或计划不适用 | 不登记操作，继续原摘要的普通启动；缺来源有固定本地提示 |
| 存储故障、版本冲突、持久占用 | 拒绝派发，不能通过普通降级绕过未决操作 |
| 应用差异或派发前复核失败 | 确定没有调用执行器时条件恢复并 Abort；恢复失败保留占用 |
| 执行器明确返回未派发 | 条件恢复，不出队、不发事件 |
| `ErrStartDispatchUncertain` 或派发中异常 | 保留 `dispatching`、设置和队列，不恢复、不自动重发 |
| 已派发但回执登记失败 | 保留可能派发记录及独立派发事实，不回滚、不重发 |
| 已登记派发但最终提交失败 | 保留 `dispatched`，后续仅重试队列事务 |

`StartDispatch` 返回 false 必须能证明尚未派发；未知结果使用上述错误标识或保留异常传播。task 的执行器只在 `exec.Start` 返回 nil 后报告成功，异步 Wait 释放句柄。重复、并发或保留到锁外的回调不能再次派发。

`RestorePreparedStart` 仅恢复持久 `prepared`，重新读取真实阶段和补丁，不信任公开视图。恢复必须持有相同的统一锁；`dispatching` 不因重启或进程列表为空而自动取消。

配套 HTTP 与网页现在提供有限恢复：完整文件仍为原摘要时可取消 `prepared`，`dispatched` 可补交原数据库事务；`dispatching` 仅查看。取消不写配置，补交不重新派发。正文严格冻结目录、操作版本和动作，未知响应只查询原记录，详见 `startup-recovery.md`。此入口尚不能恢复已修改配置，也没有开放生产文件 CAS。

## 每日设置所有权

纯补丁只允许 `DomainName` 和 `SundayEverySelectedValue` 两个字符串字段。后者对齐每日模式的周日奖励序号 0–3。补丁记录原字段是否存在、原值和自动值；恢复仅处理当前仍等于自动值的字段。后续人工修改、删除和非字符串值保持原样，原字段缺席恢复为缺席，重复恢复不创造字段。

已启用每周模式时拒绝非空每日补丁，不修改 `WeeklyDomainEnabled`、每周字段、队伍、任务开关或其他配置。顶层重复键、Unicode 大小写别名、非对象正文、额外正文和超过 1 MiB 的配置不能进入写入。

空补丁保留原始字节和摘要。原队列非空且本次全部满足时必须使用空补丁，停止填新培养秘境，同时正常派发。前次已提交自动字段的跨次归还及实际文件恢复仍需生产文件适配器，不能只凭数据库日志宣称完成。

## 队列与内部事件

内部重新计算连续完成前缀，不接受调用者提交 `CompletedPrefix` 或 `ApplyAllowed`。指纹不含当前时间，故提交时仍需真实时钟复评估；重读旧快照不会刷新源时间。

Finalize 核对稳定计划身份、版本、完整正文和连续条目 ID，只退役冻结前缀。不能按角色名删除重新加入的条目。可信缺料启动即使没有完成前缀，也递增版本，阻止旧编辑跨过启动提交。

事件为 `talent.entry.materials-ready` 和 `talent.queue.materials-ready`，表示材料条件满足，不表示角色已在游戏内升级或加点。条目事件包含下一角色和剩余数量。原队列为空、禁用或本次没有推进时不产生“全部满足”。事件 ID 由操作和稳定条目确定，事务重试不重复生成事件。

0.2.7 的材料事件桥把 outbox 接收投影与源确认放在同一 SQLite 事务，随后发送兼容的 SSE 唤醒；客户端通过独立历史接口补偿。事件表存在不代表气泡已经展示，更不代表真实游戏培养完成。
