# 培养目标技能选择与确认

日期：2026-10-28。本阶段完善配套 AutoBGI 的正式培养队列编辑和材料请求，桌宠客户端继续通过原协议只读查看队列。源码进度不改变冻结 0.2.14 程序和 ZIP 的内容。

## 真实编号与候选来源

角色面板缓存现在保留原始 `skill_id` 与 `skill_type`。旧缓存没有这些字段时保持缺省，不从数组下标、角色编号或计算器技能组推导真实技能编号。

`CharacterPlanService` 使用当前角色编号、明确元素和唯一技能全名，将原始技能与公开计算器元数据连接。A/E/Q 分类来自该元素元数据的 `PosName`，被动和不可升级项目不进入候选；`skill_type` 只保留原始值，不猜测数字含义。任一必要槽缺失、重复名称、重复编号或元素歧义都会使候选不可用。

公开候选仅包含真实技能编号和名称，计算器 `GroupID` 始终留在服务端。候选摘要为规范小写 SHA-256，绑定角色、元素、原始技能及映射资料；候选顺序重排不会产生新摘要。菜单边界还会复核元素，以及每个编号和名称是否唯一存在于同一原始角色。

## 页面操作

先保存包含角色的队列，再在对应条目点击“选择并确认目标技能”。页面固定候选元素，A/E/Q 三个选择器初始均为空；单一候选和已有绑定也不会自动选中。

逐项选择后，点击“核对所选技能”，查看角色、元素、三个技能名称和既有数值目标。最后点击“确认绑定并保存”才更新草稿并提交普通队列版本保存。取消不修改条目，也不发送保存请求。保存期间的后续数值编辑保留在草稿，已保存的同一确认令牌在成功回执后清除。

候选不足时显示原因，可以先在米游社工具显式更新角色面板，再点击队列的“刷新技能选项”。该操作只刷新公开计算器元数据；角色面板、计划数值目标和已有绑定均保持原值。需要重新打开选择流程逐项确认。

配置、目录、角色、草稿、版本、候选和生命周期状态变化都会作废待确认选择。晚到的刷新响应只有仍属于同一完整保存计划和上下文时才能接纳。

## 保存和刷新合同

`POST /api/talentPlan/config` 的每个条目可包含：

```json
{
  "targetSkills": {
    "element": "anemo",
    "skillIds": [10001, 10002, 10003]
  },
  "skillSelectionFingerprint": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa"
}
```

示例编号和摘要仅用于说明格式。`skillIds` 必须恰好三个不同的正整数，按 A/E/Q 顺序，且能在网页精确往返。绑定对象必须同时包含两个精确字段；null、部分字段、重复键、未知字段和错误类型都会被拒绝。

新绑定、改变绑定或显式再次确认必须提交当前候选摘要，并逐槽匹配实际编号。失效摘要返回版本冲突。`skillSelectionFingerprint` 是本次用户确认的版本条件，不持久化到计划；已保存的 `targetSkills` 完整保留。普通数值编辑、重排和禁用可原样回传已有绑定，不强迫元数据重新联网。保留原条目 ID 时不能清空已有绑定。

`GET /api/talentPlan/characters` 在原角色字段之外，提供可选 `skillOptions` 或 `skillOptionsReason`；GET 只读缓存。

`POST /api/talentPlan/skill-options/refresh` 仅接受：

```json
{
  "configName": "示例配置",
  "scopeId": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
  "expectedRevision": 1
}
```

接口使用原鉴权路由组，正文上限 4 KiB。同配置同时只允许一次主动刷新，远程请求期间释放一条龙队列锁。请求前、逐个远程请求前和最终响应前核对完整保存计划、账号成员及面板摘要；变化、取消或部分失败时不返回整体成功。公共元数据缓存可能已获得部分更新，计划、队列历史、库存和游戏任务不因此改变。

成功结果的 `data` 为原样 `plan`、缓存角色 `items` 和原面板 `panelUpdatedAt`。前端请求超时为 125 秒，服务端请求上下文最长两分钟。

## 材料计算和兼容

已保存绑定通过同一个辅助函数传给需求读取、显式需求刷新和背包采集准备。计算前先核对元素和三个真实技能编号，包括“面板显示等级已达标”的快捷分支；当前元素变化或技能失配时拒绝计算原目标。

选中的真实技能先映射回同元素计算器技能组，再复用已有官方材料算法。没有绑定的旧目标保持原 JSON 和指纹格式，旧计划不会自动补写技能身份。

桌宠 `/api/desktop-pet/v1/cultivation-queue` 的严格旧 DTO 保持原合同。本阶段没有在缺少能力协商时追加 `targetSkills`；桌宠显示独立技能身份需要后续兼容协议扩展。

## 验证边界

实际源码的隔离测试、竞态检查、Vue 交互验证及构建证据记录于 `skill-selection-validation-2026-10-28.json`，汇总见 `acceptance.md`。测试使用合成角色、模拟公开资料及独立 SQLite，不连接真实账号或游戏。

用户确认的技能绑定只记录目标意图，不证明基础天赋、可信源时间、库存覆盖或游戏完成。现有显示等级仍可能含加成，本地面板接收时间仍不等于来源时间。生产可信面板提供器、库存与持续预留、配置消费握手和运行终态映射仍未完成；`inventoryVerified`、`executionAvailable`、`completionEventsAvailable` 保持 false。
