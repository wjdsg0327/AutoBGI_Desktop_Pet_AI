# 基础面板已达标的无库存启动路径

日期：2026-10-28。本阶段完善配套服务的内部评估与持久事务，不更新冻结的桌宠 0.2.14 发布物，不开启生产自动出队。

## 已实现的内部合同

`TalentPlanService.EvaluationInput.Mode` 为空时继续使用已有材料评估。显式选择 `panel-targets` 后，必须提供整份已保存计划的 `Panels`，不能附带材料需求、库存证据、库存数量、覆盖范围或合成配方。

每条 `PanelTargetSnapshot` 包含稳定条目 ID、角色 ID、元素、按 A/E/Q 排列的三项官方技能编号、实际等级、排除加成的基础天赋，以及明确身份、来源版本、源时间、获取时间和可信生产者。全队列必须来自同一次面板观察，来源版本、生产者和采样时间均相同；同一实际时刻使用不同时区表示仍视为同一观察。

计划条目及内部保存输入增加值类型的 `TargetSkills`，保存目标元素和三项技能编号。证明必须与保存目标逐项相同。只有证明携带元素或技能编号、原计划没有相应绑定时不能获得授权，旅行者等变体也不能通过相同角色 ID 混用不同元素的结果。

旧条目的 `TargetSkills` 为零值，JSON 省略该字段，既有计划摘要和材料评估指纹保持原样。新绑定与等级、天赋目标一起通过计划版本比较交换保存。保留条目 ID 时不能静默清除已有技能绑定；主动清除须删除后重新加入，旧条目身份继续退役。当前网页和桌宠 v1 不提供技能身份选择，也不会自行给旧计划补齐绑定；未来接线需要具备对应选择、展示及确认能力的版本化合同。

当前材料需求快照没有技能身份，因此带明确 `TargetSkills` 的新目标不能使用旧材料评估获得授权。此约束防止新计划退回不具备同等绑定的旧证据路径。

## 整队列判断

来源必须来自宿主实际核实的生产链，`ProviderVerified` 及各证据的校验状态不能由网络调用者提供。计划和每项证据的 UID、区服、稳定条目及角色 ID 都必须匹配，三个技能编号必须完整、为正且互不重复，基础天赋范围为 1–10。

所有角色的实际等级和基础 A/E/Q 都达到保存目标后，评估才返回完整的 `CompletedPrefix` 和 `ApplyAllowed=true`。任一证明缺失、重复、多余、过期、来源批次不同、技能不符或未达标，整次评估均不可应用，不先移除部分角色，也不隐式退回材料模式。

此路径不要求库存，输入中的库存保持真正的零值；它没有把缺失库存改成已核验空库存，也不产生材料占用。跨次库存预留的独立设计见 `inventory-reservation-design-2026-10-28.md`，该账本尚未实现，不能因本阶段完成而标为可用。

## 持久化与派发边界

新面板启动记录的行版本和冻结正文版本均为 2。旧材料记录继续使用版本 1，并保持原有指纹；版本与证据模式必须严格对应，不能把旧记录改成面板解释，或把面板记录降回材料解释。

模式、完整面板证明和目标技能绑定都进入冻结摘要。准备服务复制来源数据，公开操作视图和来源返回切片不能改写私有凭据。恢复读取、登记以及最终 `BeginCommit` 均重新核对模式、计划、证明和来源有效期，使用旧摘要不能刷新时间。

全部面板已达标只能使用空每日补丁，原文件和目标文件摘要必须相等。协调器仍有界读取并核对原配置，登记 prepared，写入 dispatching，再单次派发原逻辑配置。空补丁不调用文件 CAS。只有执行器明确派发后才登记 dispatched 并在原事务里移除整份冻结前缀；明确未派发可撤销，派发未知则保留围栏和队列，不重试。

面板达标不生成现有的 `materials-ready` 事件，材料历史桥不会收到或误投影这一结论。独立的“目标已达标”通知合同尚未接通，不能将没有材料事件解释为已经完成整项通知需求，也不能把启动前的面板事实说成本次游戏运行的培养结果。

## 生产边界与验证

现有 `CharacterPlanService/Targeted.go` 的 `panel-already-met` 是展示需求来源。现有技能等级不能证明基础等级已排除命座或其他加成，本地面板更新时间也不能充当官方源更新时间，因此本阶段没有将它转换为可信 `PanelTargetSnapshot`。

生产 `StartSource` 继续返回来源不可用，没有注册配置副本启动器；`executionAvailable`、`inventoryVerified`、`completionEventsAvailable` 仍为 false。当前用户计划缺少显式技能目标时会保持不可应用。后续仍需真实来源适配、技能选择与确认合同、独立通知、库存账本和实际消费握手。

隔离回归及源码摘要统一见 `panel-targets-validation-2026-10-28.json`。验证只使用合成身份、内存执行器、独立 SQLite 和精确复制的生产领域源码，不访问真实数据库、凭据或账号缓存，不启动 AutoBGI、BetterGI、游戏或原生桌宠。

最终普通与 race 各通过 18 个顶层测试、132 个子测试，共 150 个命名测试、137 个叶场景，零失败、零跳过、零竞态报告；领域 vet、六个相关宿主包 vet 和完整主程序编译通过。21 份领域生产源码及 5 份模型副本与原文件摘要一致；主程序实际依赖与嵌入资源的 592 份输入在构建前后保持一致。首次 race 因测试夹具在两次进程间复用 SQLite 路径而失败，加入进程标识后重跑普通与 race 通过；首次失败日志保留，不将其计为通过。

验证同时覆盖旧计划 JSON 字节和材料指纹兼容、旧 schema 1 恢复、技能绑定保存与版本失效、schema/模式错配、同一时刻的不同时区表示、等待到 `BeginCommit` 时证据过期、空补丁不调用文件 CAS、明确失败和未知派发的不同恢复，以及旧材料事件仍可接收确认。面板模式终态的材料 outbox 为零，伪造材料事件被拒绝。

新增临时文件分两组各执行一次精确清理，均被自动审批以 `blocked by policy` 在执行前拒绝：测试组 41 份（含 1 份测试源、隔离生产副本及 SQLite），根验证组 3 份（旧源对照两份及仅编译的宿主 EXE）。这 44 份文件均保留在本阶段两个独立 `.validation` 目录，未重试、覆写、改名、移动或删除父目录；正常生产构建不包含这些文件。此前已拒清理的历史目标未触碰。
