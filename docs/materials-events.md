# 培养材料事件与历史补偿

日期：2026-10-28。客户端版本：0.2.7。配套 AutoBGI 需要重新构建后才提供本接口。

## 业务含义

本链路只接收已经终结的培养启动事务所产生的 `talent.entry.materials-ready` 与 `talent.queue.materials-ready`。前者表示某条目标的材料条件满足，后者表示本次非空原队列的材料条件全部满足。它们都不能证明角色已在游戏内升级、天赋已加点，或一条龙任务已完成。

可信库存与需求源时间仍未核实，生产来源继续返回 `ErrStartEvidenceUnavailable`，生产文件适配器继续拒绝配置写入。新增 `materialsReadyEvents` 只表示能够查询材料结果历史，不改变 `executionAvailable`、`inventoryVerified`、`completionEventsAvailable`。因此，当前生产来源不会凭展示缓存产生这类事件。

## 持久接收与宿主生命周期

接收表、接收水位和培养 outbox 共用 AutoBGI 的 SQLite 数据库。每次接收固定当前执行目录，最多处理 256 条待投递记录；先重新验证已终结日志、冻结计划与原事件，再在同一事务中保存展示投影、递增水位并确认源 outbox。任何步骤失败均整体回滚。不能以 SSE 消息已经入内存为由确认源事件。

收件记录保留稳定业务 ID、原操作 ID、计划 ID、原配置名、原 UID/区服、原条目和发生时间。相同 ID 重投必须与原正文一致；不同正文、损坏来源、缺页和异常水位均返回错误。接收后的历史读取仍核对原始终态，不能将孤立或被改写的投影当作可靠记录。

同一操作内先按冻结条目顺序接收，再接收整队列事件；跨操作以持久接收序号分页。事件不会提供当前预设 ID、当前队首或剩余数量；旧配置改名、删除或同名重建以后，历史仍属于原计划，不能按名字重新关联。

宿主只运行一个收件器，首次立即读取，之后每两秒处理一批。只有新增持久收件才发送既有 `server.notice` 唤醒；旧客户端继续使用原 SSE 类型白名单。退出先取消并等待收件器，再关闭协议采样和事件连接、释放协议文件锁。失败只产生限频本地提示，不重试游戏启动。

## 只读协议

能力：`features.materialsReadyEvents`。

路径：`GET /api/desktop-pet/v1/cultivation-material-events`。接口使用与桌宠其余路由相同的 `apiKey` 请求头，返回统一 envelope。禁止账号、配置名、路径和其他额外选择器。

| 请求方式 | 参数 | 结果 |
| --- | --- | --- |
| 首次建立基线 | 完全不带查询参数 | 返回当前实例、目录最近最多 100 条，按序号递增；游标定位读取事务的完整水位 |
| 增量读取 | `after`、`generation`、`executionContext` 三者各出现一次 | 返回之后最多 100 条；`hasMore=true` 时继续读取 |
| 失效代次、超前水位或目录变化 | 同上 | `410 RESYNC_REQUIRED`，重新建立历史基线 |
| 缺少接收元数据或存储损坏 | 任一合法请求 | 明确报不可用，不以空数组伪装成功，也不在 GET 中写入或修复 |

`after`、`cursor`、事件 `sequence` 与 `planRevision` 均为规范十进制字符串，范围不超过 SQLite 有符号整数上限；不用 JavaScript 浮点数保存。`generation` 是持久收件范围代次，与 SSE 的进程 `epoch:sequence` 分开。`truncated=true` 明确表示首次只返回最近一页，不承诺在桌宠显示无限历史。

事件正文包含 `businessEventId`、`operationId`、`executionContext`、`planId`、`configName`、`role`、`kind`、条目身份、版本和原始 `occurredAt`。队列事件的 `entryId`、`characterName` 为空，`characterId` 为零；不以接收时间补写发生时间。完整字段见 `api-v1.openapi.yaml`。

## 客户端消费

客户端只在服务端明确声明能力后读取，沿用当前连接的固定来源 HTTP、密钥脱敏、取消和暂停机制。首次连接、事件重同步、恢复连接和普通快照轮询都能补偿历史；`server.notice` 仅合并触发刷新，不创建另一套持续采集器。

业务水位独立于 SSE 游标。客户端以连接资料、服务地址、实例和执行目录隔离收件范围，按稳定业务 ID 及正文摘要去重。水位、去重、历史与通知尝试一起持久化，写入失败不推进内存水位；跨服务进程代次也不把相同业务结果变成新提醒。

首次基线和重同步只补历史，不补弹旧气泡。正常连续增量中的新鲜事件才可以尝试一次提醒，时间使用原始 `occurredAt`；隐藏、休眠、勿扰和气泡开关继续由通知中心处理。历史列表与当前保存队列分别展示，不根据历史事件推算游戏执行状态或当前队首。

本地最多保留十个最近使用的来源范围，每个范围展示最近一百条历史，并保留最多 4096 个业务去重身份。切回已保存的执行目录时，即使历史为空，也会更新最近使用范围，之后按该范围的水位续读。去重空间不足时只淘汰发生时间已超过六分钟的条目；新鲜窗口仍满则停止接收，不推进水位、不弹新提示。整个命令与事件日志上限为 16 MiB，旧版不含材料记录的日志仍可读取。

服务端当前不自动淘汰接收历史，数据库会随真实事件增长；客户端的一百条展示上限不代表源记录已删除。接收范围还包含持久桌宠实例身份，重建该身份不会自动继承旧实例已经确认的历史。

## 验证与限制

验证记录见 `materials-events-validation-2026-10-28.json` 与 `acceptance.md` 的 0.2.7 章节。验证只使用临时 SQLite、合成角色、模拟执行器及本机 HTTP，不读取生产账号或凭据，不修改真实 BGI 配置，也不启动游戏。

本轮没有重新验收透明窗口、混合 DPI、焦点、睡眠或内存耐久。此前 250 MB 内存目标未达标的结论保留。
