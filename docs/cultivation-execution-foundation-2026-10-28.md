# 精确需求刷新与一次性配置副本

日期：2026-10-28。本阶段继续实现 M4 的服务端依赖，不改写冻结的桌宠 0.2.14 发布产物，也不表示完整规格已经验收。

## 可直接使用的网页功能

一条龙培养队列增加“刷新本计划需求”。先保存角色、UID、区服、FIFO 次序与等级、A/E/Q 目标，再点击按钮，由服务端为已保存的每一项请求官方计算器需求。此前只有“读取缓存进度”，任意新目标可能始终没有对应的精确缓存。

新增受既有鉴权保护的 `POST /api/talentPlan/requirements/refresh`，正文仅接受：

```json
{
  "configName": "用户已保存的一条龙",
  "scopeId": "当前执行目录的64位小写摘要",
  "expectedRevision": 1
}
```

请求不接收角色、材料、库存、目标、路径或 verified。服务端重新读取计划和所属角色，按已保存目标调用 `CharacterPlanService.RefreshTargetRequirements`。同一目录与配置的并发刷新返回 409。远程请求期间不长持有队列或目录锁；每项前后及最终都核对完整计划和面板摘要。目标、身份、面板或目录发生变化时拒绝旧结果。

刷新失败不改计划、不推进队列、不启动一条龙。部分成功的远程结果只能保留为按精确请求隔离的缓存，不能伪装成整份计划刷新成功。网页也会丢弃草稿、目录、身份、版本、生命周期或组件卸载之后的迟到回复。

需求获取时间仍为本地收到官方计算结果的时间。官方响应未提供源时间时继续为 null，不使用重新读取缓存的时刻或获取时间冒充。正式 owned、missing 及执行能力没有因此升级。

## 一次性完整配置副本

`bgiStatus/one_dragon_run.go` 与 `one_dragon_run_windows.go` 增加可信宿主内部接口：

| 接口 | 作用 |
| --- | --- |
| `PrepareOneDragonRunArtifact` | 根据操作 ID、逻辑配置、目录身份、原配置完整摘要和每日白名单差异创建完整副本 |
| `ReadOneDragonRunArtifact` | 只读持久初始映射，不创建文件，不产生可派发凭据 |
| `OpenOneDragonRunArtifact` | 仅重开仍与初始正文及当前原配置相符的副本，不重新执行 |
| `OneDragonRunArtifactLease.Verify` | 从同一文件句柄重读副本，并核对当前逻辑原配置 |
| `OneDragonRunArtifactLease.Close` | 释放句柄，保留副本和恢复证据 |

以上方法由可信宿主持有既有队列和目录锁调用，不是 HTTP 文件写入 API。物理名称固定为 `__autobgi_run_<32位小写操作ID>`，JSON 内部 Name 与文件名精确一致。普通配置编辑、改名、删除、预设列表和普通启动不能访问保留名称。

完整任务定义、顺序、启用状态、NextTaskId、队伍、每周设置及未知字段均保留。允许的内容变化仅有 Name，以及 `TalentPlanService.DailyPatch` 已核准的 DomainName、SundayEverySelectedValue。空每日差异只改变运行名称，适用于之后“全部材料已满足但仍执行原一条龙”的协调分支；此处不自行判断材料满足。

原配置只在生成快照时短暂固定，不写回原文件。后续人工修改仍可正常保存，但会使本次旧确认失效。原文件与完整初始副本、manifest 分别保存在 `User/OneDragon/.autobgi-runs/<操作ID>/`，然后排他创建根目录的可执行副本。已有同名文件、半份快照和损坏映射不覆盖、不删除、不自动恢复为可执行。

映射读取会重新应用每日白名单差异，从原快照重建初始产物并逐字节、逐摘要核对。顶层与嵌套重复 JSON 键、Unicode 大小写歧义、未知或缺失的 manifest 字段、跨目录身份、非普通文件、重解析点及硬链接均不接受。运行记录上限为 32；超限保留证据并拒绝继续创建，没有自动历史清理。

Windows 目录链以相对句柄打开，并拒绝共享删除。运行文件句柄允许读取和写入，拒绝删除；这是文件身份租约，**不是正文不可变保证**。BetterGI 在启动与执行期间会保存配置，禁止写入的租约会阻断它的 `File.WriteAllText`。本实现兼容该保存方式，保存后副本若与初始摘要不同，就不能通过旧确认重新取得可派发租约。初始映射仍可供后续恢复查看。

## 任务层派发接口

`task/startup_artifact.go` 和 `startup_artifact_windows.go` 新增独立 artifact 包装器及 `StartOneDragonArtifactFrozenOnceIfIdle`。它不替换当前普通启动包装器；没有注册完整生产协调器时明确拒绝。

派发描述符绑定操作 ID、逻辑名称、原始摘要、固定物理名、固定绝对路径和初始副本摘要。最终启动锁内再次核对原配置、副本正文及内部 Name、新鲜空闲状态和程序文件，只允许调用一次执行器。普通单次启动与旧重试入口拒绝直接选择保留副本。

进程结果区分“已经创建进程”和“创建后的身份读取失败”，返回 PID、Windows 创建时刻和 Session。创建后失败不能包装成“确定未派发”，也不能因此重发。异步 Wait 只回收进程资源，不确认配置消费、游戏任务完成或删除运行副本。

固定上游源码及读取、保存顺序依据见 `bettergi-run-artifact-contract.md`。当前没有消费回显握手，文件名日志、exec.Start、进程存在及进程退出均不构成实际执行配置摘要的证明。

## 最小材料目录证据

新增 `TalentPlanService/catalog_types.go`、`catalog.go`、`catalog_evidence.go`，将真实官方计算器提供的材料 ID、完整名称与固定公共资料精确合并。目前只核对了自由教导、指引、哲学的三比一关系及忘却之峡的普通开放日。

百科 content_id 与游戏材料 ID 分开，缺少任一阶、同 ID 异名或同名异 ID 均拒绝。目录的 mapping-ready 只描述映射覆盖，不输出库存验证或启动授权。没有接入可信官方计算器提供器时保持 unavailable。

周日奖励序号仍未证实：上游 tp.json 奖励数组顺序不能代表游戏界面顺序。周日、限时全开及服务器偏移不明时拒绝建议。普通开放日建议也不直接写配置。具体事实、原文摘要、日界规则和范围见 `talent-material-catalog.md`。
