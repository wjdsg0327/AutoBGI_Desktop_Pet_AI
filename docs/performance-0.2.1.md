# 0.2.1 按需控制台与短时性能记录

记录日期：2026-10-27。程序文件版本 `0.2.1.0`，产品版本 `0.2.1`。本记录验证本轮改动，不替代 Windows 11、可见动画或八小时稳定性验收。

程序 SHA-256：`340d3f63e631bbbc5cb3e23b80ce40942f37851741f7939867132571f8250107`。

## 条件与方法

- Windows 10 专业版 `10.0.19045`，i5-12490F，12 个逻辑处理器。有效显示器 DPI 未核验。
- 只有一份客户端实例。`APPDATA/TEMP/TMP` 指向新建隔离目录，没有生产连接或 APIKey。
- 本地离线资料使用回环地址，`autoConnect=false`；持久凭据引用仅为测试资料字段，没有读取或写入系统凭据，也没有连接该地址。
- 先使用正常窗口启动方式运行角色，再通过正式重复启动恢复通道打开控制台。角色未被窗口工具枚举，无法确认其实际可见性；控制台由原生窗口枚举和 WebView UIA 读取确认，截图未成功。
- 两阶段使用同一隔离实例、同一配置和 WebView 缓存，在暖机后各采 13 点，采样间隔五秒，另含系统查询耗时。
- 工作集按宿主及实际 WebView2 父子进程链求和，包含共享页重复计量。私有提交内存另列，不当作私有驻留工作集。
- CPU 为每个 PID 加启动时间身份的最大累计 CPU 减首样本基线，除首末样本时间差与逻辑核数。最后一次采样后的等待不纳入 CPU 分母。两阶段均计得 3 秒累计 CPU；进程在采样间退出时仍可能漏计尾部 CPU。

## 原生检查与限制

第二次启动在五秒期限内退出，退出码 0；原客户端继续运行，同路径客户端进程数仍为一。控制台此前没有 renderer，恢复后增加一个；原生 UIA 读取到：

- 页面地址 `http://wails.localhost/?view=panel`。
- 版本 `v0.2.1` 与测试资料名“隔离离线检查”。
- 尚未连接、仅查询模式以及无可靠任务状态的真实页面内容。

在另一份无连接资料的空白隔离目录启动后，约 0.921 秒内观察到两个 renderer，日志包含两条 WebView 环境创建成功，确认首次设置仍会创建角色与控制台；不据此断言画面可见。

控制台截图两次均报 `window capture timed out: timed out waiting on channel`。首次失败后重新枚举并选择了当前窗口，重试仍失败，停止 Windows 输入自动化。没有把关闭隐藏、草稿恢复、透明、拖动、穿透、托盘可见性或全屏焦点标为原生通过。程序退出使用精确路径及启动时间校验后的测试进程树终止，不能替代正常 Quit 清理验收。
