# 0.2.13 拖动会话与布局变化保护

本轮为已有拖动增加宿主令牌，处理由源码确认的协议缺口：前端已经按旧原点计算的绝对坐标，可能在布局纠正、缩放或交互设置变化后才到达。宿主现在先验证手势仍然有效，再接纳目标位置。

这是桌宠目录内的阶段性增强，不代表完整开发规格已经验收。未运行生产 AutoBGI、BetterGI 或游戏，也未改变显示器、网络或电源设置。

## 前后端协议

| 绑定 | 输入与返回 | 行为 |
| --- | --- | --- |
| `BeginPetDrag` | 无参数；返回 `{ token, x, y }` 或 `null` | 先撤销旧手势，再读取逻辑原点并签发随机令牌 |
| `DragPetTo` | `token, x, y`；返回布尔值 | 只接受当前令牌和相同坐标环境；拒绝后前端结束所属手势 |
| `PetDragged` | `token`；返回布尔值 | 仅消费一次有效结束请求，并调用位置保存；返回值表示请求被接纳，不表示磁盘写入已获确认 |
| `CancelPetDrag` | `token`；返回布尔值 | 仅撤销匹配的手势，不移动窗口或主动保存位置 |

前端使用 Wails 根据 Go 生成的 `PetDragStart`，没有另建协议类型。开始、移动、结束和取消共用串行调用链；下一手势读取起点前，先完成旧手势的在途调用和令牌清理。迟到的开始回包也会归还原令牌，不会清理后来的手势。

松开时使用松开事件的最终指针位置，然后结束一次。取消不撤销已经接受的位移；原有防抖移动通知和退出保存仍按实际窗口位置工作。普通拖动保留边缘部分可见规则，逐帧只更新内存，不逐帧同步磁盘。

## 失效依据

桌宠业务服务在偏好保存成功后、释放配置锁前，为可见、穿透、缩放和勿扰变化递增独立代次。普通轮询、读取快照、无关偏好和相同值保存不递增。即使异步广播跳过“隐藏后显示”等中间状态，旧手势仍会因为代次不同失效。配置已经保存而通知记录处理失败时，同样递增；配置保存失败时不递增。

原生层同时比较当前服务偏好与已应用偏好，拒绝窗口尚未完成相关变更时的开始、移动或结束。会话环境包括实际窗口尺寸、偏好缩放、策略代次和规范排序的屏幕签名。签名保留原始显示器标识、工作区、主屏标记及 `ScaleFactor` 位值，包含临时无效屏幕；仅枚举顺序变化不取消手势。

设置应用采用单一消费者。原生调用期间重入的新快照只保留最高版本，等当前调用完整返回后再应用；相关门禁持续到这一轮消费完成。原生调用异常后保持拒绝拖动，下一份快照会完整重应用窗口设置以恢复，避免旧调用在新设置之后才落地。

重置、DPI 通知、收到的显示/工作区系统消息和睡眠意图会撤销旧令牌。开始请求另检查撤销版本，防止读取原点期间的重入重置或新开始被旧请求覆盖。原生窗口和文件操作均在宿主状态锁外执行。

每次操作以最后一次读取服务策略并验证当前会话为接纳边界。其后并发提交的设置会影响后续请求；已经进入原生调用或被接纳的位移不会被令牌机制追回。

收到坐标环境变化后，本次拖动会结束；用户重新按下即可开始新手势。穿透关闭鼠标交互，角色动画仍继续；隐藏、页面不可见、休眠或勿扰按原有规则暂停动画。

## 验证范围

具体执行结果、输入摘要和清理状态见同目录 `drag-session-validation-2026-10-28.json`。最终发布核对记录位于 `.validation/drag-session-20261028/`，发布包不包含验证工作目录、测试源码或用户资料。

纯会话状态、实际服务偏好写入、实际前端控制器和 Vue 事件处理分别在受控环境验证。原生宿主验证使用实际方法及合成窗口、屏幕、调度和位置存储依赖，不能据此判定真实 Windows 调度或文件保存已经通过。

系统消息保护只覆盖实际收到的相关消息，环境比较只覆盖读取时观察到的事实。不能据此保证发现未广播、未收到消息且在两次读取间已经复原的布局变化。任一程序窗口收到 DPI 消息时都会保守取消当前角色拖动。

尚未重新实测透明窗口、触摸、整窗穿透、游戏焦点、混合 DPI、拔屏和真实休眠。250 MB 内存目标继续未通过。可信库存归属与覆盖、生产培养配置提交及可靠游戏任务终态仍未完成；本轮没有开放这些执行能力。
