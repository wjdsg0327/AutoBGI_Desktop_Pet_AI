# 一条龙配置与培养队列生命周期

记录日期：2026-10-27。本节记录配套 AutoBGI 服务端源码的新增能力，桌宠 Windows 便携包仍为 0.2.5；本轮没有重建、替换或启动生产 AutoBGI。

## 用户可见行为

网页的一条龙配置可以带着已保存的培养队列改名。计划绑定身份、条目 ID、加入时间、FIFO 次序及各项等级和 A/E/Q 目标保持不变；旧名称保存递增版本墓碑。删除配置时，已保存队列清空，活跃条目身份永久退役。原配置文件保存在执行目录的 `User/OneDragon/.autobgi-lifecycle/<operationID>/original.json`，普通配置列表不显示归档目录。

目标名称已有活跃计划时拒绝覆盖，包含保存过的空计划。目标文件存在也拒绝覆盖。大小写同键改名暂不支持。未完成的操作持续占用原名与目标名，涉及名称的读取与写入返回明确错误；其他名称可以继续编辑。

操作失败后保留恢复信息。服务启动时尝试恢复当前执行目录的未完成操作；页面另提供显式恢复按钮。配置列表只读发布目录身份与待恢复标记，即使删除已经移走最后一个配置文件，页面仍能显示恢复入口。读取配置、队列和进度不会暗中恢复或重放原写入。

删除确认说明文件归档与条目退役。页面在 BetterGI 运行确认之前冻结名称、版本、目录与请求内容；未保存或正在保存的队列阻止开始改名和删除。恢复允许保留失败草稿；有草稿时不会自动切换到新名称或覆盖原编辑器。

## 持久协议

`TalentPlanService.Store` 增加四个内部方法：

| 方法 | 作用 |
| --- | --- |
| `BeginLifecycle` | 同一事务保存源、目标的版本与稳定身份快照，登记文件摘要并占用名称 |
| `PendingLifecycles` | 有界只读列出当前目录未完成意图 |
| `CompleteLifecycle` | 队列迁移或退役、递增墓碑、日志完成和释放占用同事务提交 |
| `AbortLifecycle` | 仅供可信文件协调器证明未移动或已完整回滚后使用；没有公开强制取消 HTTP 入口 |

日志不保存凭据、路径或配置正文。`prepared` 状态本身就是持久名称占用。公开 `Load` 和所有 `Save/Rename/Delete` 写事务均检查占用，不能只依赖进程内锁。完成时重新核对两侧的存在状态、版本、墓碑和计划身份；无活跃源时同样推进墓碑，使操作前读到空缺或旧墓碑的保存请求失效。

显式恢复接口为 `POST /api/talentPlan/lifecycle/recover`，仅接受：

```json
{"expectedScopeId":"0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef"}
```

示例摘要是合成值，实际提交必须复用读取配置列表得到的摘要。接口拒绝查询参数、未知或重复字段、非 JSON、多个对象及超过 1 KiB 的请求。现有创建、保存、改名和删除请求新增可选 `expectedScopeId`；旧调用可省略，新页面始终提交。`force` 仅用于原有 BetterGI 运行确认，不能绕过版本、目录或恢复冲突。

## 文件协调与恢复

恢复固定每一级目录句柄，拒绝已有重解析点，全部子项通过 NT 相对目录句柄打开和移动。普通文件句柄拒绝其他句柄写入与删除；改名使用不替换已有文件的 `NtSetInformationFile`。提交前重新读取归档和目标的句柄正文并验证摘要，旧名称必须缺席。

先写完整替换暂存文件并同步，再把原文件移动到归档，最后发布目标。删除只归档原文件。每次暂存采用独立随机名称，中断留下的半文件不被覆盖；同一操作目录达到 64 项后停止继续暂存。配置正文上限 1 MiB，同时最多 32 条未完成操作。

| 当前文件状态 | 恢复动作 |
| --- | --- |
| 原文件摘要正确、没有归档和目标 | 生成并核对暂存内容，归档原文件，再发布目标或完成删除 |
| 原文件缺席、归档摘要正确、目标缺席 | 改名继续发布目标；删除继续数据库提交 |
| 原文件缺席、归档和目标摘要正确 | 继续数据库提交 |
| 原文件与归档同时存在，或两者都缺席 | 保留文件、队列与名称占用，报告冲突 |
| 任意相关文件摘要或类型变化 | 保留现场并报告冲突，不覆盖外部修改 |
| 权限、共享、数据库或其他状态无法确定 | 保持未完成，允许稍后显式重试 |

改名仅修改顶层 `Name`，保留未知字段。单个非规范大小写的名称字段会被正确替换；顶层重复键和 Unicode 大小写别名会被拒绝，避免序列化重排改变其他配置的最终解释。软件升级后如无法重新构造相同目标摘要，也保持未完成。

定时启停配置组、旧 OneLong 写入和角色培养写入已接入同一名称占用与目录锁，错误时不继续依赖该写入启动任务。归档不自动清理，不提供强制覆盖或强制释放占用。

## 验证与边界

数据库验证为 16 个顶层组、72 个子场景，race 连续 5 轮共 440 次通过。Windows 文件与 SQLite 集成为 8 个顶层组、28 个子场景，race 连续 5 轮共 180 次通过，零失败、零跳过。覆盖真实文件移动、崩溃状态重建、数据库触发器失败、外部文件变化、文件句柄保护、无覆盖发布、旧请求失效及暂存上限。

独立 Windows 实验验证了目录共享标志不足以阻止原位重解析点变化，因此实现使用相对句柄访问；普通路径访问可能跟随变化时，相对打开、创建和移动均失败关闭，没有写入另一目录。两个 JSON 名称与别名回归分别以 race 运行五次通过。旧写入口的 5 个测试组各重复五次通过。HTTP、Vue、构建及精确源码摘要见 `configuration-lifecycle-validation-2026-10-27.json`。

本轮验证使用首次运行前已预置绝对虚拟 BetterGI 路径的独立运行目录、SQLite 和合成配置，没有读取真实凭据、控制游戏、改变网络或休眠。支持范围是本地 Windows 盘；UNC 与重解析点目录不开放自动生命周期操作。

此实现验证进程中断及可重试写入失败，不承诺突然断电、磁盘损坏或文件系统回滚与 SQLite 之间的共同持久性。外部程序仍可在旧名称缺席后创建同名文件；该文件不会继承已迁移队列，旧请求仍受墓碑保护。当前没有把原生进程派发纳入这份配置事务，普通一条龙启动与真实游戏行为仍需单独验收。

可信库存生产者、启动准备与提交、每日配置条件恢复及可靠培养完成事件仍未完成，所有自动培养执行标志继续为 false。
