# 桌宠已保存技能目标展示

日期：2026-10-28。本阶段将网页已保存的元素和 A/E/Q 实际技能编号接入桌宠正式队列，只发布用户目标意图，不开放生产培养执行。

## 用户可见行为

桌宠“已保存培养队列”沿用读取配置、选择预设、读取队列的入口，在“明确目标”单元格显示保存的元素及 A、E、Q 编号。保持现有纸感卡片、浅绿色标签和手机横向滚动，不增加候选选择、编辑或执行按钮。

显示由已接纳响应决定：schema 1 显示“技能绑定未知 · 旧服务未提供”；schema 2 的显式 null 显示“旧计划尚未绑定技能”；完整对象显示保存元素及实际编号。缺省或 undefined 不能冒充第二版的显式空绑定。断线、暂停或同一上下文读取失败保留历史并标记过期，能力、连接、实例或预设改变会作废迟到结果。

## 协议及实现

基础能力仍为 `cultivationQueue`，附加能力为 `cultivationQueueSkillTargets`。两者同时明确开启才请求 `?presetId=...&schemaVersion=2`；默认旧请求、旧类型和旧 Schema 保持原字段集。版本只接受字面量 2，参数各一次、顺序可互换，拒绝编码拼写和未知或重复项。宿主未实现第二版返回 501；客户端拒绝双向版本失配，不重试或改成另一版。

每条第二版记录必须包含 `targetSkills:null` 或仅含 `element`、`skillIds` 的对象。七种元素使用规范小写名称，三项编号为互异的正 JavaScript 安全整数，严格保持保存的 A/E/Q 次序。绑定不公开候选、确认摘要、推测技能名或可信来源证明。完整独立合同和合成示例位于 `contracts/cultivation-queue-v2.schema.json`、`contracts/cultivation-queue-v2.example.json`。

宿主两版映射复用同一次队列与执行目录冻结范围内的进度视图，避免分别读取旧字段与绑定而混合版本。服务端读取前后核对预设内容版本和目录摘要；客户端继续校验实例、预设、形状、时间与未知库存，服务层再次核对 profile、generation、epoch、暂停周期及请求时能力。

首次 Wails 绑定生成发现网络结果的 `MarshalJSON` 会被生成器降为 `any`。服务层因此增加没有自定义序列化方法的具象 Display DTO，双指针只用于保留 schema 1 省略与 schema 2 明确 null/object 的编码区别。最终实际生成明确的 Result、Plan、Entry 和技能目标 interface；前端仍从现有方法返回类型推导条目，没有手写协议副本，也没有新增 Wails 方法或轮询。
