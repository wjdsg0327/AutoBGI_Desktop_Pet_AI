# 培养启动记录核对与有限恢复

日期：2026-10-28。本轮更新配套 AutoBGI 的 Go 和网页源码，桌宠客户端仍为 0.2.7。桌宠源码、交付包与本文位于 `AutoBGI_Desktop_Pet_AI`；配套接口和原启动入口修改位于主项目。

## 可用行为

一条龙配置页增加独立的“培养启动待核对”区域，依据配置列表提供的执行目录身份读取记录。即使配置列表为空，也保留该区域。启动未决与配置改名、删除的生命周期恢复分别处理，不再把前者送入旧的改名、删除恢复接口。

| 持久阶段 | 网页操作 | 服务端证明 |
| --- | --- | --- |
| `prepared` | 确认文件未变并取消准备 | 仍为准备阶段，当前完整配置 SHA-256 与冻结的原文件摘要一致 |
| `prepared` 且文件变化、不可读 | 只读 | 不尝试写回或用局部字段相等替代完整文件核对 |
| `dispatching` | 只读 | 结果未知；超时、重启、空进程列表和用户确认均不能证明未派发 |
| `dispatched` | 补提交培养队列 | 执行器此前已明确确认派发，只重试原冻结计划的数据库事务 |
| `aborted` / `finalized` | 单条查询及同动作幂等核对 | 终态由持久记录提供，不根据待处理列表为空推断 |

取消准备不写配置文件。补提交不再次启动、不恢复配置，也不表示角色已在游戏内升级或加点。补提交沿用原事务的稳定身份、版本和材料事件去重约束。

若请求超时或发生服务端错误，网页只查询原 `operationId`。只有同一目录、操作、确认版本及预期终态全部吻合，才显示处理成功。不会自动再次 POST，也不会重放此前失败的保存、改名、删除或启动请求。编辑草稿继续保留。

同目录刷新在原 POST 结束之前延后，保持操作锁。目录切换使旧确认和迟到结果失效；若新目录的配置读取失败，旧目录草稿可以继续显示，但新目录的无未决结果不能解锁旧配置的启动、保存和队列修改，必须先成功读取一致目录的配置。

## HTTP 合同

接口注册在已有的 `/api/talentPlan` 分组，复用 AutoBGI 原有鉴权。它们不是桌宠 v1 的新增命令能力。

| 方法 | 路径 | 约束 |
| --- | --- | --- |
| GET | `/api/talentPlan/start-operations?expectedScopeId=...` | 当前目录全部未决记录，最多 32 条 |
| GET | `/api/talentPlan/start-operations/:operationId?expectedScopeId=...` | 原记录，包括终态 |
| POST | `/api/talentPlan/start-operations/:operationId/recover` | 显式确认单条记录和允许动作 |

`expectedScopeId` 为 64 位小写十六进制执行目录摘要，`operationId` 为 32 位小写十六进制稳定身份。GET 只接受一个精确的 `expectedScopeId` 查询参数；错目录不能退回当前默认目录。响应使用 `Cache-Control: no-store`。

POST 使用 `application/json`，正文最多 4096 字节，且只接受以下三个精确、不重复的字符串字段：

```json
{
  "expectedScopeId": "<64 位小写十六进制目录摘要>",
  "expectedOperationVersion": "<64 位小写十六进制确认版本>",
  "action": "cancel-unmodified"
}
```

另一允许动作是 `finalize`。请求不能提交阶段、可信布尔值、补丁、配置内容或来源证据；不接受额外查询参数、未知字段、大小写别名和尾随正文。

安全摘要包括操作、目录、稳定计划身份、配置名、UID/区服、计划版本、连续满足项数、剩余项数、阶段、时间、确认版本、允许动作和固定提示。计划版本与最终版本是十进制字符串，避免 JavaScript 丢失 uint64 精度。摘要不返回完整配置、库存来源、文件路径、原始冻结日志或凭据。

`operationVersion` 由固定字段顺序的不变安全摘要计算。阶段迁移另行核对；确认版本不随时间或阶段改变，便于响应丢失后查询原记录和同动作重试。对已经取消的记录请求 `finalize`，或对已经提交的记录请求取消，仍返回冲突。

| HTTP | 错误码 | 语义 |
| --- | --- | --- |
| 400 | `TALENT_START_INVALID` | 格式、字段、动作或身份格式不合法 |
| 409 | `TALENT_START_CONFLICT` | 目录、确认版本、阶段或完整文件已经变化 |
| 409 | `TALENT_START_PENDING` | 派发结果未知，当前只能查看 |
| 503 | `TALENT_START_UNAVAILABLE` | 存储或依赖暂不可用；固定提示不公开内部错误正文 |

原队列和一条龙启动接口遇到启动未决时，也返回独立的 `TALENT_START_PENDING`。该错误优先于其包裹的旧生命周期错误，网页因此不会误调用旧恢复接口。

## 旧入口的关闭与启动保护

`task.StartOneDragon` 与新增的 `StartOneDragonWithPreparation` 共用宿主守卫。后者接收宿主内置的前置动作，先检查本执行目录全部未决启动与目标配置生命周期，再执行关闭程序、关闭游戏和原启动策略。

保护覆盖本轮接线的普通一条龙、定时任务、MCP 定时任务、日志关键词、JS 一条龙日志和命令行入口。`OneLongTask` 将真实启动失败返回调用方，失败时不再发送后续成功截图或打印任务完成。独立的关闭命令、配置组和计划表入口仍保持各自原行为，不宣称所有进程控制动作都受培养守卫覆盖。

锁顺序为可选的 `OneLong` 启动互斥、队列互斥、执行目录读锁、task 最终启动锁。本地旧入口提示在守卫之外读取，避免重新获取同一队列锁。一次回调不能重入、重复调用或在守卫返回后再执行；宿主吞掉动作错误也不能将其转换为成功。

旧入口继续使用原有日志就绪检查与重试策略。本轮持有队列和目录锁直到这段过程结束，慢启动或重试会延迟其他队列、材料读取及目录切换。保护未决记录与保持原重试策略是当前取舍，不能据此声称所有旧入口已接入培养提交。

## 交付与验证边界

本轮提供配套后端、网页源码及隔离构建验证，不替换 `menu/web/dist`、已有 AutoBGI 可执行文件、桌宠 0.2.7 EXE 或 ZIP。部署新网页需要按主项目流程重新构建前端并嵌入主程序；隔离前端构建不等于生产程序已经包含新界面。

详细测试统计、源码摘要、构建目录与清理结果见 `startup-recovery-validation-2026-10-28.json`。验证使用隔离 SQLite、假配置与计数回调；没有执行真实关闭、游戏派发或生产服务控制。

以下工作继续保留：

- 准备阶段配置已被自动补丁修改时的真实恢复与经过验证的 Windows 配置 CAS。
- 前一次自动每日字段的跨次所有权归还。
- 具备可靠 UID/区服、真实源时间、覆盖范围和完成证据的库存生产链。
- `dispatching` 的外部权威派发事实；本轮不提供手动清除或按进程状态猜测的入口。
- 真实服务及游戏联调、原生窗口矩阵和性能目标。

生产来源仍明确返回 `ErrStartEvidenceUnavailable`，生产配置适配器仍拒绝写入。`executionAvailable`、`inventoryVerified`、`completionEventsAvailable` 继续为 false；独立材料历史的可读能力不改变这些限制。
